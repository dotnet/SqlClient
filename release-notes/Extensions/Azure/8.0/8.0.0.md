# Release Notes

## Stable Release 8.0.0 - 2026-11-26

`Microsoft.Data.SqlClient.Extensions.Azure` aligns with the `8.0.0` driver.
See the [core release notes](../../../8.0/8.0.0.md).
The family `AssemblyVersion` is `8.0.0.0`: unchanged from preview1, but changed from `7.0.0.0`
in the 7.x family. .NET Framework consumers upgrading from 7.x should review binding redirects.

## Changes Since [8.0.0-preview1](8.0.0-preview1.md)

### Changed

- Updated Azure.Core from `1.63.0` to `1.65.0`, MSAL and its broker from `4.91.1` to `4.92.0`,
  and cryptography/caching dependency floors from `10.0.13` to `10.0.15`. Family dependencies
  align to `8.0.0`. No additional authentication APIs or algorithms change in this delta.
  ([#5031](https://github.com/dotnet/SqlClient/pull/5031),
  [#5041](https://github.com/dotnet/SqlClient/pull/5041))

## Cumulative Changes Since [7.1.2](../7.1/7.1.2.md)

The cumulative view includes the dependency delta above and these preview1 changes.
The Windows WAM missing-parent-window guidance was already shipped in 7.1.2 and is not a new fix.

### Added

#### Authentication diagnostics

*What Changed:*

- Forwarded built-in MSAL, allowlisted Azure.Identity, and SqlClient token-acquisition events
  to `Microsoft.Data.SqlClient.EventSource`, keyword `AuthenticationTrace` (`0x2000`), IDs 22-27.
  ([#1846](https://github.com/dotnet/SqlClient/issues/1846),
  [#4872](https://github.com/dotnet/SqlClient/pull/4872))

*Who Benefits:*

- Support teams can investigate built-in Entra ID authentication without replacing its provider.

*Impact:*

- Use `0x2000` for authentication, or `0x2002` with ordinary tracing. Use `dotnet-trace` on
  modern .NET and ETW/an `EventListener` on .NET Framework.
- Extension-owned requests keep PII logging disabled. Correlation is best effort; some events
  have an empty connection ID and can originate from application-owned credentials. Treat
  captures as sensitive, and interpret the final outcome rather than every credential failure.
  Application-owned `AccessTokenCallback` credentials are not covered. See the
  [logging sample](../../../../doc/samples/SqlAuthenticationLogging_Example.cs).

### Changed

- **Breaking dependency change:** this package owns Azure Attestation JWT validation and
  IdentityModel dependencies. `Attestation Protocol=AAS` requires an explicit matching-version
  reference to this extension; otherwise enclave setup fails with `InvalidOperationException`.
  No new public validator API is introduced.
  ([#4017](https://github.com/dotnet/SqlClient/issues/4017),
  [#4790](https://github.com/dotnet/SqlClient/pull/4790))
- Azure.Core replaces Azure.Identity as the credential dependency; namespaces stay unchanged.
  Remove direct Azure.Identity references older than 1.21.0 or upgrade to 1.21.0+;
  Azure.Identity.Broker users need 1.6.0+.
  ([#4749](https://github.com/dotnet/SqlClient/pull/4749))
- Reflective authentication discovery can be disabled. For explicit trimmed/Native AOT
  registration, disable both authentication switches at publish time and preserve the provider's
  own contracts. The driver's independent Azure Attestation loader is unaffected. See the
  [Abstractions notes](../../../Extensions/Abstractions/8.0/8.0.0.md).
  ([#4821](https://github.com/dotnet/SqlClient/pull/4821))
