# Release Notes

## Preview Release 8.0.0-preview1 - Unreleased

Draft for `Microsoft.Data.SqlClient.Extensions.Azure`, aligned with the driver package version
and preview build suffix. The source cutoff, branch-cut baseline, and pending-work rules are
defined in the [core release notes](../../../8.0/8.0.0-preview1.md).
The family `AssemblyVersion` changes to `8.0.0.0`; .NET Framework consumers should review
binding redirects. This is not a publication announcement.

### Added

#### Authentication diagnostics

*What Changed:*

- Forwarded built-in MSAL, allowlisted Azure.Identity, and SqlClient token acquisition
  diagnostics to `Microsoft.Data.SqlClient.EventSource`, under the new
  `AuthenticationTrace` keyword (`0x2000`). Event IDs 22-27 contain `message`, `source`,
  and `connectionId`.
  ([#1846](https://github.com/dotnet/SqlClient/issues/1846),
  [#4872](https://github.com/dotnet/SqlClient/pull/4872))

*Who Benefits:*

- Applications and support teams diagnosing Entra ID token acquisition failures without
  replacing the built-in authentication provider.

*Impact:*

- Use mask `0x2000` for authentication only or `0x2002` to include ordinary tracing.
  `dotnet-trace` works on modern .NET; use ETW or an `EventListener` on .NET Framework.

  ```text
  dotnet-trace collect --process-id <pid> --providers Microsoft.Data.SqlClient.EventSource:0x2000:5 --rundown false
  ```

- Extension-owned requests keep PII/unsafe support logging disabled. Correlation is best
  effort, and some Azure.Identity events have an empty connection ID. Uncorrelated events
  can include application-owned credential activity; treat captures as sensitive.
- `DefaultAzureCredential` can log failed/skipped credentials before succeeding. Interpret
  the final selection and SqlClient outcome, not each individual failure as an open failure.
  Cached tokens/pooled connections can skip authentication entirely.
- Application-owned `AccessTokenCallback` credentials are not covered. See the
  [logging sample](../../../../doc/samples/SqlAuthenticationLogging_Example.cs) and
  [EventListener sample](../../../../doc/samples/SqlAuthenticationEventListener_Example.cs).

### Changed

#### Azure Attestation validation moved out of the driver

*What Changed:*

- This package now owns the Azure Attestation JWT validator and its IdentityModel
  dependencies; the enclave provider remains in the core driver.
  ([#4017](https://github.com/dotnet/SqlClient/issues/4017),
  [#4790](https://github.com/dotnet/SqlClient/pull/4790))

*Who Benefits:*

- Applications not using Azure Attestation no longer receive those dependencies from core.

*Impact:*

- **Breaking dependency change:** `Attestation Protocol=AAS` requires an explicit,
  matching-version reference to this package. Without it, enclave setup fails with
  `InvalidOperationException`. No new public validator API is introduced.

#### Azure.Core supplies credential types

*What Changed:*

- Replaced the Azure.Identity dependency with Azure.Core. Updated shipping dependency
  versions to the source floors below.
  ([#4749](https://github.com/dotnet/SqlClient/pull/4749),
  [#4880](https://github.com/dotnet/SqlClient/pull/4880))

*Who Benefits:*

- Applications use the consolidated Azure SDK credential implementation.

*Impact:*

- Credential types retain their `Azure.Identity` namespace. Remove older direct
  Azure.Identity references or upgrade to 1.21.0 or later to avoid duplicate-type errors.
  Azure.Identity.Broker users need 1.6.0 or later.
- Use the same version of every installed SqlClient family package. The driver reports
  mismatches with build warning `SQLCLIENT001`.
  ([#4815](https://github.com/dotnet/SqlClient/pull/4815))

#### Authentication bootstrap ownership

- Authentication discovery/bootstrap now belongs to Abstractions' shared registry.
  `Switch.Microsoft.Data.SqlClient.EnableAzureExtensionDiscovery` controls reflective
  Azure authentication discovery, defaults to `true`, and caches its first value.
  Applications can disable discovery and explicitly register a provider instead.
- For explicit registration in trimmed/Native AOT applications, disable both
  `EnableAppConfig` and `EnableAzureExtensionDiscovery` at publish time and preserve
  the provider's own dependencies. See the
  [Abstractions notes](../../../Extensions/Abstractions/8.0/8.0.0-preview1.md).
- Azure Attestation uses a separate driver loader: disabling authentication discovery
  does not disable attestation loading or remove its Azure-extension requirement.
  ([#4821](https://github.com/dotnet/SqlClient/pull/4821))

### Fixed

- Windows WAM interactive-authentication errors for a missing parent window explain
  supported alternatives: supply a parent window, use `Active Directory Default` with a
  non-interactive credential, or use a custom application ID with WAM disabled.
  The original MSAL error code and inner exception are retained (Windows only).
  ([#4858](https://github.com/dotnet/SqlClient/pull/4858))
