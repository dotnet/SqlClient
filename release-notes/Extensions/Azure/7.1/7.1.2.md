# Release Notes

## Stable Release 7.1.2 - 2026-11-12

This release aligns `Microsoft.Data.SqlClient.Extensions.Azure` with
[Microsoft.Data.SqlClient 7.1.2](../../../7.1/7.1.2.md) and improves Windows authentication
diagnostics. Use matching driver and companion package versions.
The assembly retains `AssemblyVersion 7.0.0.0`; upgrading from `7.1.1` does not require
new .NET Framework strong-name binding redirects.

## Changes Since [7.1.1](7.1.1.md)

### Fixed

#### Actionable WAM errors for windowless hosts (Windows only)

*What Changed:*

- Interactive authentication errors with MSAL code `window_handle_required` now include
  SqlClient-specific guidance while preserving the original error code and inner exception.
  ([#4854](https://github.com/dotnet/SqlClient/issues/4854),
  [#4916](https://github.com/dotnet/SqlClient/pull/4916))

*Who Benefits:*

- Applications running in Windows hosts without a parent window, including Azure Functions
  local worker processes, can identify supported authentication alternatives.

*Impact:*

- Applications with a window can supply its handle through
  `ActiveDirectoryAuthenticationProvider.SetParentActivityOrWindowFunc`.
- Windowless hosts should use `Authentication=Active Directory Default` with a configured
  non-interactive credential. Interactive authentication without WAM requires a custom
  `ActiveDirectoryAuthenticationProviderOptions.ApplicationClientId` and `UseWamBroker=false`.
- WAM remains enforced for SqlClient's first-party application ID. This is diagnostic guidance,
  not an automatic fallback or a change to authentication selection.
