# Release Notes

## Preview Release 8.0.0-preview1 - 2026-11-06

`Microsoft.Data.SqlClient.Extensions.Abstractions` 8.0.0-preview1 is version-aligned with
the driver. See the [core release notes](../../../8.0/8.0.0-preview1.md) for features
and compatibility changes.
The family `AssemblyVersion` changes to `8.0.0.0`; .NET Framework consumers should review
binding redirects.

### Added

#### Public authentication configuration section handlers

*What Changed:*

- Abstractions now exposes public authentication configuration types, including
  `SqlClientAuthenticationProviderConfigurationSection` and
  `SqlAuthenticationProviderConfigurationSection`.
  Existing driver-qualified app.config declarations remain supported.
  ([#4816](https://github.com/dotnet/SqlClient/pull/4816))

*Who Benefits:*

- Applications can use authentication configuration contracts directly from Abstractions.

*Impact:*

- Existing section names, schema, and empty defaults are preserved. Modern targets expose
  ConfigurationManager as a transitive compile dependency.

#### Direct authentication registration and trim/AOT-analyzed asset

*What Changed:*

- Authentication registration/bootstrap now lives in Abstractions. The driver uses its
  shared registry directly, and `SqlAuthenticationProvider.GetProvider`/`SetProvider`
  no longer load the driver through reflection.
- Moved `SqlAuthenticationInitializer` into this package, with a driver type forward
  preserving existing references. Added a `net10.0` asset with trimming/AOT analysis.
  ([#4821](https://github.com/dotnet/SqlClient/pull/4821))

*Who Benefits:*

- Applications explicitly registering custom authentication providers can remove reflective
  bootstrap during trimmed or Native AOT publication without depending on driver loading.

*Impact:*

- `Switch.Microsoft.Data.SqlClient.EnableAppConfig` controls authentication configuration
  on .NET Framework and modern .NET. The new
  `Switch.Microsoft.Data.SqlClient.EnableAzureExtensionDiscovery` controls reflective
  Azure authentication discovery. Both default to `true` and cache their first value.
- For explicit registration in trimmed/Native AOT applications, disable both paths at
  publish time and construct/register providers for the required authentication methods
  before opening connections:

  ```xml
  <ItemGroup>
    <RuntimeHostConfigurationOption Include="Switch.Microsoft.Data.SqlClient.EnableAppConfig"
                                    Value="false" Trim="true" />
    <RuntimeHostConfigurationOption Include="Switch.Microsoft.Data.SqlClient.EnableAzureExtensionDiscovery"
                                    Value="false" Trim="true" />
  </ItemGroup>
  ```

- Runtime changes alone cannot remove code at publish time. Trimmed JIT applications can
  retain reflective paths if they preserve configuration infrastructure, handlers,
  provider/initializer constructors, and discovered Azure option members. Enabled paths
  emit trimming warnings and, for Native AOT, dynamic-code warnings; enabling a switch
  does not root those contracts.
- The driver's retry/switch-override readers remain separately gated on modern .NET only.
  Azure Attestation uses an independent driver loader and does not consult the
  authentication discovery switch. This change is not full-driver Native AOT support.

### Changed

#### Authentication configuration and provider precedence

*What Changed:*

- Modern and legacy authentication configuration sections remain supported. Invalid settings
  and provider activation failures are reported through trace diagnostics.
  ([#4860](https://github.com/dotnet/SqlClient/pull/4860),
  [#4821](https://github.com/dotnet/SqlClient/pull/4821))

*Who Benefits:*

- Applications can diagnose configuration failures and control authentication provider
  selection.

*Impact:*

- Configured providers/initializers take precedence over application registrations, which
  take precedence over discovered Azure defaults. Failed explicit configuration does not
  silently reuse an earlier provider/default; a failed method can be recovered by explicit
  successful application registration. An initializer failure blocks defaults for otherwise
  unregistered methods because its intended methods are unknown.
- Registration failures are traced; null providers, unsupported methods, and recoverable
  callback failures return `false` without replacing the existing provider. Check the
  return value from `SetProvider`. Callbacks run outside the lookup/publication lock and
  can be retried after concurrent or reentrant changes.
- Configuration/discovery is attempted once after normal completion or recoverable failure;
  correct configuration and restart to retry bootstrap. Fatal errors propagate.
- Family package versions must match the driver, including preview suffixes.
  ([#4815](https://github.com/dotnet/SqlClient/pull/4815))

## Target Platform Support

- Package assets: .NET Framework 4.6.2, .NET Standard 2.0, and .NET 10.0.
- With the 8.0 driver: .NET Framework 4.6.2+ on Windows, or .NET 10.0+ on Windows,
  Linux, and macOS.
