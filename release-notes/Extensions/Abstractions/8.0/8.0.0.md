# Release Notes

## Stable Release 8.0.0

`Microsoft.Data.SqlClient.Extensions.Abstractions` aligns with the `8.0.0` driver.
See the [core release notes](../../../8.0/8.0.0.md).
The family `AssemblyVersion` is `8.0.0.0`: unchanged from preview1, but changed from `7.0.0.0`
in the 7.x family. .NET Framework consumers upgrading from 7.x should review binding redirects.

## Changes Since [8.0.0-preview1](8.0.0-preview1.md)

### Changed

#### Authentication diagnostics use Abstractions-owned resources

*What Changed:*

- Authentication configuration, registration, and token diagnostics use resource-backed messages
  owned by this package rather than driver resource helpers or hard-coded English text.
  Five existing messages move with their 13 translated cultures; additional messages fall back
  to neutral English where no translation exists.
  ([#4852](https://github.com/dotnet/SqlClient/pull/4852),
  [#5044](https://github.com/dotnet/SqlClient/pull/5044))

*Who Benefits:*

- Applications receive culture-aware diagnostics without loading the driver to format an error.

*Impact:*

- Exception types and authentication contracts are unchanged, but exact exception/trace wording
  can change. Deploy this package's satellite assemblies when localized messages are required.
- UI culture selects resources; current culture formats arguments. Recoverable resource/format
  failures are traced and produce a key-and-arguments fallback; fatal errors propagate.
- Updated the ConfigurationManager dependency floor from `10.0.13` to `10.0.15` for
  netstandard2.0/net10.0 and aligned the Logging dependency to `8.0.0`.
  ([#5041](https://github.com/dotnet/SqlClient/pull/5041))

## Cumulative Changes Since [7.1.2](../7.1/7.1.2.md)

The cumulative view includes the diagnostic/dependency delta above and these preview1 changes:

### Added

- Public authentication configuration section handlers, including
  `SqlClientAuthenticationProviderConfigurationSection` and
  `SqlAuthenticationProviderConfigurationSection`; driver-qualified declarations remain supported.
  ([#4816](https://github.com/dotnet/SqlClient/pull/4816))
- Direct shared authentication registration/bootstrap and `SqlAuthenticationInitializer`,
  with a driver type forward preserving compatibility, plus a trim/AOT-analyzed net10.0 asset.
  ([#4821](https://github.com/dotnet/SqlClient/pull/4821))

### Changed

- Configured providers/initializers precede application registrations, which precede discovered
  Azure defaults. Failed explicit configuration does not silently reuse an earlier/default
  provider. Failures are traced; check `SetProvider` results. A successful explicit registration
  can recover a failed method. Configuration/discovery is attempted once; restart after repairs.
  ([#4860](https://github.com/dotnet/SqlClient/pull/4860),
  [#4821](https://github.com/dotnet/SqlClient/pull/4821))
- Authentication `EnableAppConfig` and `EnableAzureExtensionDiscovery` switches default to
  `true` and cache their first values. Disable both at publish time for explicit registration
  in trimmed/Native AOT applications, then register every required provider. Runtime values
  alone do not remove reflection. Enabled reflective paths need retained contracts and report
  warnings; this is not full-driver Native AOT support. The driver's retry/switch-override
  configuration and Azure Attestation loader remain separate.
- Use matching family versions, including prerelease suffixes; driver builds warn on mismatch.
  ([#4815](https://github.com/dotnet/SqlClient/pull/4815))

## Target Platform Support

- Package assets: .NET Framework 4.6.2, .NET Standard 2.0, and .NET 10.0.
- With the 8.0 driver: .NET Framework 4.6.2+ on Windows, or .NET 10.0+ on Windows, Linux, and macOS.
