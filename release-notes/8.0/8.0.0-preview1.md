This first 8.0 preview describes changes since [7.1.1](../7.1/7.1.1.md), the latest published
release at the snapshot date. The decimal-parameter, access-token-expiry, and in-flight pool-clear
fixes already included in 7.1.1 are not repeated as new features. The Source Link correction
already backported to 7.1 is also excluded.

The driver and its four companion packages use matching versions, including the final preview
build suffix. For the 8.0 family, `AssemblyVersion` changes from `7.0.0.0` to `8.0.0.0`.
.NET Framework applications should review strong-name binding redirects when upgrading.
`Microsoft.SqlServer.Server` and native SNI remain independently versioned.

### Added

#### Opt-in reset of pooled transaction isolation levels

*What Changed:*

- Added `Switch.Microsoft.Data.SqlClient.EnableTransactionIsolationLevelReset`, defaulting to
  `false`. When enabled, a SqlClient-tracked session isolation level change is reset to
  `READ COMMITTED` before pooled reuse when no existing enlistment or active delegated
  transaction root remains.
  ([#96](https://github.com/dotnet/SqlClient/issues/96), [#4330](https://github.com/dotnet/SqlClient/pull/4330))

*Who Benefits:*

- Applications that otherwise inherit an isolation level left by a previous user of a pooled connection.

*Impact:*

- Enable the switch before opening connections. A reset adds a round trip only when required and
  uses the remaining connection-open timeout budget. Known Azure Synapse dedicated SQL pool
  endpoints are excluded. The default preserves existing behavior.
- A user-issued `SET TRANSACTION ISOLATION LEVEL` command alone does not mark the connection
  for this reset. The switch does not guarantee cleanup of arbitrary T-SQL isolation-level changes.

#### Additional TimeOnly write paths (net10.0 only)

*What Changed:*

- Added `TimeOnly` support for `SqlBulkCopy` DataRow/DataTable sources and `SqlParameter` values
  with `SqlDbType.Variant`, writing SQL `time` values. Corrected the related debug assertion for
  table-valued parameters containing variant values.
  ([#4604](https://github.com/dotnet/SqlClient/pull/4604))

*Who Benefits:*

- Applications using modern .NET time-only values in bulk-copy and variant-parameter workflows.

*Impact:*

- These paths no longer require conversion to `TimeSpan`. This does not introduce `TimeOnly`
  support on .NET Framework.

### Changed

#### Breaking change: minimum modern runtime is .NET 10

*What Changed:*

- Replaced the `net8.0` and `net9.0` implementation targets with `net10.0`. .NET Framework
  4.6.2 support is retained.
  ([#4238](https://github.com/dotnet/SqlClient/issues/4238), [#4779](https://github.com/dotnet/SqlClient/pull/4779))

*Who Benefits:*

- Applications moving to the .NET 10 runtime and dependency servicing band.

*Impact:*

- Upgrade modern applications to .NET 10 before adopting this preview, or remain on a compatible
  earlier driver release. The retained `netstandard2.0` reference and unsupported-platform
  assemblies do **not** provide runtime support for .NET 8 or .NET 9.

#### Breaking change: Azure Attestation requires the Azure extension

*What Changed:*

- Moved Azure Attestation token validation and the IdentityModel dependencies out of the core
  driver into `Microsoft.Data.SqlClient.Extensions.Azure`.
  ([#4017](https://github.com/dotnet/SqlClient/issues/4017), [#4790](https://github.com/dotnet/SqlClient/pull/4790))

*Who Benefits:*

- Applications that do not use Azure Attestation no longer receive these IdentityModel
  dependencies from the core driver.

*Impact:*

- Applications using `Attestation Protocol=AAS` must explicitly reference a matching version of
  `Microsoft.Data.SqlClient.Extensions.Azure`. Without it, enclave session setup fails with
  `InvalidOperationException`.
- The Azure extension now uses Azure.Core instead of a separate Azure.Identity dependency.
  Existing credential namespaces are unchanged. Remove direct Azure.Identity references older
  than 1.21.0, or upgrade to 1.21.0 or later; Azure.Identity.Broker users need 1.6.0 or later.
  See the [Azure extension notes](../Extensions/Azure/8.0/8.0.0-preview1.md).
  ([#4749](https://github.com/dotnet/SqlClient/pull/4749))

#### Breaking changes: reference API and argument validation corrections

*What Changed:*

- Reference assemblies now match implementation accessibility and sealing: non-public
  constructors are no longer exposed as implicit public constructors, and the data-classification
  types are correctly marked `sealed`. The nonexistent
  `SqlBatchCommand.CanCreateParameter` setter is removed from the .NET Framework reference API.
  ([#4826](https://github.com/dotnet/SqlClient/issues/4826), [#4832](https://github.com/dotnet/SqlClient/pull/4832))
- `SqlParameterCollection.RemoveAt(int)` now throws `ArgumentOutOfRangeException` for an invalid
  index, rather than `IndexOutOfRangeException`. The collection indexer's behavior is unchanged.
  ([#4874](https://github.com/dotnet/SqlClient/pull/4874))
- In globalization-invariant mode, character-type `SqlMetaData` construction requires an
  overload with an explicit LCID (net10.0 only).
  ([#4457](https://github.com/dotnet/SqlClient/pull/4457))

*Who Benefits:*

- Consumers get compile-time feedback for reference APIs that previously failed at runtime,
  consistent collection argument validation, and explicit text metadata locale selection.

*Impact:*

- Code that instantiated inaccessible types, derived from sealed data-classification types, or
  assigned the nonexistent setter must be corrected. Update exception handling around
  `RemoveAt(int)` to catch `ArgumentOutOfRangeException`.
- Use a `SqlMetaData` constructor with `locale` or `localeId` for character columns in
  globalization-invariant mode. This does not add general globalization-invariant connection support.

#### Package layout and family-version validation

- Managed driver implementations now reside in `lib/net462` and `lib/net10.0`, rather than
  duplicated RID-specific managed DLL paths. Custom deployment scripts that copied
  `runtimes/<rid>/lib/<tfm>/Microsoft.Data.SqlClient.dll` must use the new layout. Native SNI
  remains in its separate packages.
  ([#4673](https://github.com/dotnet/SqlClient/pull/4673))
- Consumer builds now emit warning `SQLCLIENT001` when installed SqlClient family package
  versions differ, including preview suffixes. This warning does not fail builds by default.
  Use matching versions of the driver and installed companions; native SNI and
  `Microsoft.SqlServer.Server` are excluded. `SqlClientEnforceFamilyVersions=false` disables
  the check.
  ([#4815](https://github.com/dotnet/SqlClient/pull/4815))

#### Windows connection pool identity isolation

- Pool identity now includes the Windows logon session, isolating network-only impersonation
  sessions even when their local SID is the same (Windows only). Separate logon sessions can
  therefore create separate pools even for the same account. Reusing a token or duplicated
  token from the same session preserves reuse. Both pool implementations guard background
  creation against a mismatched identity.
  ([#4814](https://github.com/dotnet/SqlClient/pull/4814))
- See [connection pooling and impersonation](../../doc/connection-pooling-impersonation.md)
  for migration and connection-count implications.

#### Trimming and authentication configuration

- Added `Switch.Microsoft.Data.SqlClient.EnableAppConfig`, defaulting to `true` (net10.0 only).
  Set it to `false` to disable app.config-based retry configuration, authentication-provider
  configuration, and AppContext switch overrides. To remove those configuration-reading paths
  during trimming, fix the switch at publish time:
  ([#4697](https://github.com/dotnet/SqlClient/pull/4697))

  ```xml
  <ItemGroup>
    <RuntimeHostConfigurationOption Include="Switch.Microsoft.Data.SqlClient.EnableAppConfig"
                                    Value="false" Trim="true" />
  </ItemGroup>
  ```

- Setting the switch only at runtime does not eliminate trim warnings. .NET Framework continues
  to read app.config.
- Reduced trim/AOT warnings through source-generated JSON serialization, diagnostic annotations,
  and related changes (net10.0 only). These are incremental improvements, not a claim of complete
  Native AOT support.
  ([#4683](https://github.com/dotnet/SqlClient/pull/4683), [#4684](https://github.com/dotnet/SqlClient/pull/4684),
   [#4688](https://github.com/dotnet/SqlClient/pull/4688), [#4703](https://github.com/dotnet/SqlClient/pull/4703),
   [#4801](https://github.com/dotnet/SqlClient/pull/4801))
- Exposed the authentication configuration section handlers from Abstractions, with type forwards
  preserving existing driver-qualified app.config declarations. Configuration reading and
  provider activation retain their existing behavior.
  ([#4816](https://github.com/dotnet/SqlClient/pull/4816))

#### Other changes

- Reduced allocations and cache contention in Always Encrypted key handling, and simplified the
  asynchronous setup phase of `SqlBulkCopy`. This does not include the unmerged per-row async
  loop rewrite.
  ([#4256](https://github.com/dotnet/SqlClient/pull/4256), [#4687](https://github.com/dotnet/SqlClient/pull/4687))
- Added diagnostics for database-context mismatches after transparent reconnection; this is
  instrumentation, not a change to recovery behavior.
  ([#4130](https://github.com/dotnet/SqlClient/pull/4130))
- Added USERAGENT bits reporting the configured async and ProcessSni compatibility switches;
  parser defaults and effective behavior are unchanged. This change is already merged in the
  source snapshot but is assigned to the 8.0.0 milestone rather than preview1.
  ([#4911](https://github.com/dotnet/SqlClient/pull/4911))
- Updated shipping dependencies, including `System.Security.Cryptography.Pkcs` and
  `Microsoft.Bcl.Cryptography` 10.0.13 to address the cryptography dependency advisories tracked
  in [#4843](https://github.com/dotnet/SqlClient/issues/4843). See the dependency tables below
  and companion notes.
  ([#4848](https://github.com/dotnet/SqlClient/pull/4848), [#4880](https://github.com/dotnet/SqlClient/pull/4880))

### Fixed

- Managed SNI now treats an explicitly configured `HostNameInCertificate` as the sole expected
  certificate hostname, rejecting a certificate that matches only the connection destination
  (net10.0, managed SNI only). Certificate-chain validation and `ServerCertificate` matching
  behavior are unchanged. Review configurations that previously relied on the destination-name fallback.
  ([#4905](https://github.com/dotnet/SqlClient/pull/4905))
- Fixed `SqlDataReader.HasRows` incorrectly returning `false` when multiple informational
  messages precede the first row.
  ([#4773](https://github.com/dotnet/SqlClient/pull/4773))
- Fixed XML streaming failures for fragments that begin with text by explicitly selecting
  UTF-16LE when creating the XML reader.
  ([#4757](https://github.com/dotnet/SqlClient/pull/4757))
- Fixed `SqlBulkCopy` losing `money`/`smallmoney` type identity when writing `sql_variant` values.
  ([#4727](https://github.com/dotnet/SqlClient/pull/4727))
- Fixed configurable retry logic retrying a command outside its original transaction after
  the error aborted that transaction.
  ([#4728](https://github.com/dotnet/SqlClient/pull/4728))
- Reasserted non-`ReadCommitted` ambient isolation levels when a pooled connection reattaches
  to the same transaction with a pending reset. This correctness fix is unconditional and can
  add one round trip; it is separate from the opt-in isolation reset switch.
  ([#4335](https://github.com/dotnet/SqlClient/pull/4335))
- Isolated cached enclave sessions by attestation protocol as well as server, database, and URL.
  ([#4829](https://github.com/dotnet/SqlClient/pull/4829))
- Fixed retry-provider loading and resolution to use SqlClient's current `AssemblyLoadContext`
  rather than the default context (net10.0 only). Collectible contexts using managed SNI can
  unload; this does not promise unloadability with native SNI.
  ([#4588](https://github.com/dotnet/SqlClient/pull/4588))
- Prevented eager native SNI initialization on non-Windows platforms (net10.0 on Linux/macOS).
  ([#4700](https://github.com/dotnet/SqlClient/pull/4700))
- Fixed a nullable execution-timer race causing `InvalidOperationException` in statistics
  bookkeeping, and corrected active soft-connection counter drift when the default wait-handle
  pool reclaims abandoned connections. These changes do not make concurrent connection use supported.
  ([#4875](https://github.com/dotnet/SqlClient/pull/4875), [#4725](https://github.com/dotnet/SqlClient/pull/4725))
- Restored the missing `SqlParameterCollection.Add(string, object)` implementation and exposed
  `Microsoft.Data.SqlClient.Server.TriggerAction` in the reference assembly (net462 only).
  The former remains obsolete; prefer `AddWithValue` or explicitly typed parameters.
  ([#4832](https://github.com/dotnet/SqlClient/pull/4832))

### Known issues and incomplete work at this snapshot

- Native AOT work remains incomplete; a warning-free application publish is not guaranteed.
  ([#1947](https://github.com/dotnet/SqlClient/issues/1947))
- Internal async enclave-provider and delegate groundwork has merged
  ([#4541](https://github.com/dotnet/SqlClient/pull/4541), [#4621](https://github.com/dotnet/SqlClient/pull/4621),
   [#4886](https://github.com/dotnet/SqlClient/pull/4886)), but command-execution wiring
  ([#4887](https://github.com/dotnet/SqlClient/pull/4887)) and async key-store integration
  ([#4585](https://github.com/dotnet/SqlClient/pull/4585)) are still open and are **not included**.
  Do not interpret the groundwork as end-to-end asynchronous Always Encrypted execution.
- Open reports include unobserved managed-SNI receive exceptions during MARS connection disposal
  ([#4679](https://github.com/dotnet/SqlClient/issues/4679)) and pool pruning during physical
  connection creation ([#4755](https://github.com/dotnet/SqlClient/issues/4755)). No fix for either
  report is claimed in this snapshot; they are not assertions of new 8.0 regressions.
- Other open or closed-unmerged milestone PRs are excluded. Reconcile the final milestone and
  release source before publishing.
